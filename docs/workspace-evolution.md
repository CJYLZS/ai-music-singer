# 仓库演进复盘：一条"实验账本"式的流水线

> 覆盖范围：根仓库 `CJYLZS/ai-music-singer` 截至 2026-11-11 的 52 个提交（2026-08-03 → 2026-11-11）。
> 上游项目（GPT-SoVITS / SoulX-Singer / seed-vc / a25rig / echomimic3）各有独立仓库，
> 在本仓库中**零跟踪**，不在本文范围内；它们与本仓库的交互方式见 §8。

## 摘要

- **52 个提交、112 个跟踪文件、单一作者**。44 个提交在 2026 年 8 月，8 个在 11 月（内容是 9 月中旬做完、11-11 才整理入库的）。
- 这不是一个"写功能"的仓库，而是一个**编排层 + 实验室账本**：`singing/` 里 69 个文件，其中大量是 `eval_*.py` / `w_*.py` / `probe_*.py`。
- 演进主线只有一句话：**用可复现的度量，把"哪个参数该当默认"一个个钉死；钉不下来的写清楚为什么否掉。**
- 支撑这条主线的三件事：单变量配对 A/B、固定 seed 的噪声纪律、以及 `AGENTS.md`（431 → 3583 行，40/52 个提交都改它）。

## 1. 仓库的定位

初始提交（`763fd3d`，2026-08-03，1962 行 / 10 文件）就定下了形态：

```
BS-RoFormer 分离 → karaoke 提主唱 → RMVPE 提 F0 → 参考选段
→ PC-NSF-HiFiGAN 音域扩展 → SoulX-Singer SVC → 相似度评测
```

配套三件套：`sing.py`（分阶段、可续跑的 CLI）、`singing/w_*.py`（各阶段 worker）、
`eval_sim.py` / `eval_stab.py`（音高分桶相似度、音色稳定性）。

关键自述是提交信息里的第一句：**"编排层，串起四个上游项目（各自独立 git 仓库 + venv，依赖冲突不可混装）"**。
这条定位决定了后续所有事情：本仓库只拥有"流程、参数、度量、结论"，模型与权重永远在别处。

## 3. 分阶段叙述

### P0 起步（08-03）：把流水线立起来

初始提交之后立刻做了两件"提速"的事：分离产物按输入+权重 md5 缓存（同歌重跑 140s→4s）；
以及 SVC 的静音段推理优化（305.8s→212.9s）。同一会话内 `AGENTS.md` 被追加两次。

从这里能看到后面一直沿用的习惯：**先把流程跑通并量出每个阶段的耗时/收益，再谈参数**。

### P1 参数化（08-04）：一天之内改掉全局默认

这一天 6 个提交，把影响最大的几个默认值定了下来：

- CFG 3 → **0.5**（`5123349`）：上游默认把条件放大 3 倍，而条件是 whisper 内容特征 + F0，
  放大条件等于放大原唱残留 —— 扫点后 0.5 峰值、且 `cfg=0` 都优于 3。
- `--pitch-shift` 支持 **auto**：按段落在八度上对齐，只在 ≥6 半音差时触发，三首歌里两首是 bit-identical。
- 引入 `--seed` / `--rescale-cfg` / `--num-overlaps`：把**随机性变成实验变量**。
- DP 段级选择差点被当成默认：先测出 λ=1 比 λ=0 高 0.0024，紧接着在 `4112f6c`
  自我纠正「低于 0.004 噪声底，是噪声拟合」，默认回退为 λ=0。

这一天确立了仓库最重要的纪律：**默认值必须来自配对实验，且增益要显著大于噪声底。**
同时留下第一批"排除结论"：`n_steps` 已饱和、whisper 去偏越去越差、`reverse_diffusion_v2` 训练配方不匹配。

### P2 度量升级（08-06→09）：缺什么指标就造什么

`af50008` 是一个大提交：kNN 内容特征替换（α=0.2）+ ext 批量移调（2.22× 提速、10 首 bit-identical）
+ 一次性新增 `eval_cer.py`、`eval_triad.py`、`paired_eval.py`。

动机很直接：kNN 编辑的是内容特征，而当时只有音色指标 —— **指标看不到的代价就不算代价**。
于是有了 CER（吐字）、triad（获得/难度/残留 + impostor 归一化）、paired（公共窗符号检验）。
这也是后来 kNN α 最终停在 0.2（而不是只看 SIM 会选的 0.4）的技术前提。

`e609477` 的 MILP 选段则是反例：全曲 10 首验证后收益不足，**不设默认**，代码留着但降级为工具。

### P3 画面与一次架构摇摆（08-10→13）

08-10 起，仓库第一次跨出"声音"：MV 出片文档、KTV 字幕、口型改用真歌词强制对齐、mix 跟随伴奏包络。

08-12 是唯一一次大架构赌博：把 SVS（乐谱控制合成）插进主链，变成
`原曲 → SVS → select-svs → prompt_svs → SVC`，并改默认（`1d3b1a7`）。
**不到 24 小时就撤回**（`48b182b`），改回"参考选段直接进 SVC"、加 `--ref-is-clean`。
同一天 `bf65b39` 把选段切成 [1s,4s] 两级并采用 DBS 第 2 轮贪心。

这段历史的价值在于展示了**可回滚性**：SVS 层虽然最终被判死（P6），但当时是以"默认可切回"的方式接入的，
所以撤回成本只有一个提交。它同时也解释了后来 `--svc-prompt svs` 一直以"备选臂"而非唯一路径存在。

### P4 质量工程（08-14→17）：把"听感"拆成可测的项

- `b30649c`：口型时间轴改为直读 LRC（KRC 行级锚点 + 行内均摊 + 能量截止），弃用长音频强制对齐。
- `50d824c`：漏音检测 + 定点修复两阶段（检测默认开，修复可选）。
- `b67705b`：SingMOS 接入默认 eval，NSF 后处理作为可选。
- `bb5be30`：源音色归一化预处理实验 + 两份调研文档进 `docs/`。
- `168b818`：kNN α **改回 0.2** —— 在追光者上暴露吐字回归，证明 α 的符号按歌分向，不能全局取 0。
- `7f886ae` / `8fadc4f`：漏音检测的 impostor 池为空误报、拼接采样率 bug 两个修复。

这一阶段的模式是"**一个指标暴露一个盲区 → 补一个工具或一个修复提交**"。

### P5 成品化（08-19→21）

`mv.py` 取代根目录 `render.sh`，成为分阶段（slice/lyrics/cues/beats/visemes/intro/render/subs）、
可续跑的 MV 入口；口白 TTS 加了语速参数与"重渲可省"的参考复用；
`c44e829` 把口白 TTS 换成唱歌混合数据训练的 SoVITS e12，并补了 **SIM 天花板标定**——
因为"SIM 下降"到底是变差还是刻度变了，必须先有天花板才能判断。

### P6 收束（08-25→27）：判死与定稿

`a167a26`（28 文件、4539 行）是最大的一次提交：SVS 路线全线归档为否定结论，四个臂
（自动转录 → SOFA 时间轴 → 手工修 MIDI → 键盘录制）全部跑完；判据是最强的一臂
（人类直接演奏乐谱、误差定义为零）依然不可用 —— 所以瓶颈是**音符表示本身丢了颤音/气声/转音**，
不是音准。同时把 12 个 `svs_*.py`、4 个 `probe_*.py`、`anal_*.py` 入库（带 docstring 写清假设与结论），
删掉一次性脚本，`.gitignore` 补上 20G 的上游克隆。

接着是低音填充（`7cd7c31` 实现 → `1ac3eb7` 三首歌 A/B → `3546988` 结论：仅一首显著，不设默认）。

最后 `4e1d4a9` 段落级 SVC 成为默认，用五个指标同时汇报（CER/SingMOS/drift/worst/SIM），
`b066802` 定稿参数（seg12/19/svc22/minrun0.2）并全量重跑出基线。

### P7 回归（11-11）：隔了两个月的一次整理

9 月中旬实际做的是日文歌 aLIEz 的整条链路（逐字歌词源、日文口型、漏音修复、建模），
以及一个长期稳定性问题（537s 参考嵌入在 16GB 卡上随机 OOM）。
11-11 这批 8 个提交把它们拆成独立主题入库：嵌入磁盘缓存 → yrc 逐字源 → 行尾兜底 →
日文口型 → 批量 TTS → 补丁存档 → aLIEz 复盘 → render 会话结论。

它暴露了流程的一个缺口：**工作区里可以躺两个月不提交的工作**。补救方式是事后按主题重切，
保证每个提交可单独 review、可单独回滚。

## 4. 方法：这个仓库是怎么"想"的

### 4.1 一次只动一个变量，且固定 seed

所有 A/B 都成对跑：`--seed` 固定（常见 1234 或 1），只改被测参数。
噪声底被反复标定：**±0.004 SIM 的 seed 噪声**，任何小于 ~0.01 的差异都视为未测出。
`--n-seeds` 与 DP 段级选择就是在这个前提下诞生的。

### 4.2 指标先行：先能测，再能调

| 工具 | 回答的问题 |
|---|---|
| `eval_sim.py` | 音高分桶的音色相似度 |
| `eval_stab.py` | 相邻窗 drift / 掉音色窗 / 最差窗 |
| `eval_dual.py` | 双锚点基准 |
| `eval_triad.py` | A/B/C 三角（获得 / 难度 / 残留）+ impostor 归一化 |
| `paired_eval.py` | 两臂公共窗 + 符号检验 |
| `eval_cer.py` | 吐字（ASR + CER，固定 VAD 种子） |
| `eval_sim_ceiling.py` | 天花板标定（判断"下降"是否是刻度错觉） |
| SingMOS / NISQA | 自然度 |

规律：**先出现一个指标无法解释的现象，再补一个指标**。
kNN 的吐字代价（CER）、SIM 的天花板错觉、漏音的归一化误报，都是这样被发现的。

### 4.3 默认值的门槛

一个候选要成为默认，至少要满足：配对实验、固定 seed、增益大于噪声底、在 ≥3 首上可复现，
并且**不破坏已有指标**（或明确记录交换关系，例如 cfg 用 SIM 换 drift）。
不满足的降级为"工具/备选臂/默认关"，并在 `AGENTS.md` 写下否掉的理由。

### 4.4 记录即交付：`AGENTS.md` 是主产物

- 431 行 → 3583 行，40/52 个提交改过它，其中 8 个提交**只**改它。
- 结构是"按日期和主题的节"，每节带结论与数字，常以 **当前默认 / 备选 / 结论是否定的 / 不设默认** 结尾。
- 配套文档分工：`README.md` = 操作手册（怎么出片）、`docs/` = 调研与复盘、
  `OPTIMIZATION.md` = 待验证清单（明确写"尚未实测"）、`docs/patches/` = 上游补丁存档。

这套体系的作用是**防重复踩坑**：被删掉的方案（VoxCPM2 / Vevo2 / HiFi-Glot / Step-Audio / IndexTTS）
条目仍留在文档里，只标注"已从磁盘删除"。

### 4.5 提交即最小叙事单元

- 单会话 1–6 个提交，主题单一，信息体常用"改了什么 + 数字 + 为什么"。
- 前缀约定：`AGENTS:` / `docs:` / `feat:` / `sing.py:` / `segprompt:` / `mix:` / `cues:` / `leak:` / `eval:` / `emb:` / `lyrics:`。
- 大变更一次提交（`a167a26` 28 文件），小改动单独提交（行尾修复 17 行）—— 粒度取决于"能否单独回滚"。

## 9. 当前流水线：逐阶段职责与模型/算法

`sing.py --stages all` 的默认链是：

```
sep → stems4 → ref-sep → f0-target → select → ext → svc → eval → leak-detect
```

`mix` 是可选后置阶段（先验收纯人声再混伴奏）；`svs / select-svs / cascade / post-nsf / leak-repair`
是可选支线。下面按数据流逐个说明**这一阶段负责什么、用什么模型/算法、默认值是多少**。

### 9.1 `sep` — 把歌声拆成主唱与伴奏

- **职责**：歌曲 → `vocal.wav`（人声总和）+ `acc.wav`（伴奏）；再对 vocal 跑 karaoke 模型拆出
  `lead.wav`（主唱）与 `backing.wav`（和声/伴唱）。
- **模型**：BS-RoFormer `model_bs_roformer_ep_317_sdr_12.9755`（SDR 12.98）
  → mel-band-RoFormer `mel_band_roformer_karaoke_becruily`。均由 `bsroformer.Roformer_Loader` 加载。
- **默认/坑**：产物按「输入文件 md5 + 权重 md5」缓存，同歌重跑 140s→4s。
  karaoke 模型有概率把**同一个人的声音**劈进 lead/backing 两边（aLIEz 27-44s），
  判据是逐秒 `lead` 相对 `lead+backing` 的电平 + 两 stem 的 F0 是否相同。
  紧随其后的 `stems4` 再用 4-stem 权重（`bs_roformer_4stems_ft`）把伴奏拆成 drums/bass/other，
  产物里的「鼓点 + bass 骨架」可作为 `--mix` 的替代伴奏。

### 9.2 `ref-sep` — 清理参考素材

- **职责**：把参考音频（可能是带 BGM 的录音/翻唱）跑同样的两级分离，产出 `refsep2/lead.wav`
  作为音色锚点；`--ref-is-clean` 时跳过。
- **模型**：同 9.1（BS-RoFormer + karaoke）。
- **为什么必须**：SVC 的 prompt 会直接进模型当 in-context mel，带 BGM 的参考会把伴奏当音色学进去。

### 9.3 `f0-target` — 提取原唱旋律

- **职责**：从 `lead.wav` 逐帧提取 F0，写 `target_f0.npy`（50Hz 网格）。下游的选段、移调量计算、
  SVC 的 F0 条件全依赖它；也是 SVC 分段切分的依据。
- **模型**：RMVPE（SoulX-Singer 预处理权重 `rmvpe.pt`），取 50Hz 帧率。
- **坑**：先跑这一步再跑 `select`，否则分段键不上；静音段/清音段的 F0=0 是正常的，不要当坏帧过滤。

### 9.4 `select` — 从参考里挑出音色锚点 + 补频段缺口

- **职责**：在参考人声里选出总长 ≤45s 的片段，构成 `prompt.wav`；再按"歌曲频段分布 − 锚点频段分布"
  的缺口，决定要移调哪些源段，交给 `ext`。产物是 `prompt.wav` / `prompt_ext.wav` 与候选清单。
- **算法**：候选切分采用**混合两级切法**（细切 1s、长切 4s），在 2 半音一格的音高网格上做贪心覆盖；
  默认用 **DBS（Diverse Beam Search）第 2 轮**——第 g 轮排序键减去 `λ×该段已被前几轮选中的次数`
  （λ=0.1），防止反复挑同一批高音段。增益按时长归一化（`gain/dur**1.0`）。
- **默认**：`--select-min-sec 1.0`、`--max-prompt 45`、`--dbs-group 2`；`--anchor-min-ratio 1.0` 表示
  "素材够宽就把 45s 全留给干净锚点，移调预算为 0"（此时 `prompt_ext` 与 `prompt` 字节一致）。
- **被否掉的分支**：MILP 求解器（`cov_anchor`）全曲 10 首均值仅 +0.0012、一半歌变差且慢 19.7×，
  降级为单歌可选；"覆盖率"作为目标函数被否证 9 次——它和 SIM 不是同向的。

### 9.5 `ext` — 用神经声码器给参考补高音/低音

- **职责**：把选中的源段按缺口所需的半音数移调，追加进 `prompt_ext`（**锚点在前、移调段在后**，
  绝不替换锚点），让参考的音域覆盖歌曲的旋律范围。
- **模型**：PC-NSF-HiFiGAN 44.1k（`pc_nsf_hifigan_44.1k_hop512_128bin_2025.02`，method=`nsfhifigan`，
  音高检测 RMVPE）。做法是 `adjust_f0_semitones` 改 F0 曲线后由 NSF 声码器重合成，而不是 DSP 变调。
  回退引擎是 seed-vc（DiT flow matching，`--f0-condition`）。
- **默认**：`--ext-method nsf`、单段最大 +8 半音、源段复用惩罚 3.0（等价半音）、按 5 组批量移调
  （5 次 fork 合 1 次，2.22× 提速，10 首 bit-identical）。
- **为什么不用全量重合成**：过一遍声码器即使 0 半音也会掉 ~15% 音色相似度，所以"锚点原样保留"是硬约束。

### 9.6 `svc` — 零样本歌声转换（核心）

- **职责**：把 `lead.wav` 的音色换成参考人物的音色，输出 `vocal.wav`；`segprompt` 模式下按段分别选参考。
- **模型**：SoulX-Singer（权重 2.7GB 的 flow-matching SVC）。三个部件：
  - `WhisperEncoder`（whisper-base）提**内容特征**，`f0_to_coarse` 把 F0 编码成 361 个 bin 的 embedding；
  - `CFMDecoder`：条件流匹配（conditional flow matching）+ DiT，Euler 积分 32 步；
  - `MelSpectrogramEncoder`：把 prompt 作为 in-context mel 送进解码器（音色从这里来）。
- **关键默认**：`--cfg 0.5`（上游 3.0 被否，CFG 放大会把输出推回原唱）、`--n-steps 32`（已饱和）、
  `--rescale-cfg 0.75`、`--knn-alpha 0.2` / `--knn-k 4`（kNN-VC 式内容特征替换，检索池是**完整参考**，
  分块编码绕开 whisper 30s 硬顶）、`--seed` 固定可复现、`--pitch-shift auto` 按段做八度对齐。
- **segprompt（默认）**：先按静音做 DP 切分（段长约束 [15,25]s），每段算中位 F0 后从候选池选音域
  匹配的参考（预算 45s），每段前后各带 2s 上下文一起送 SVC（只保留中间）——因为冷启动段首音质差。
- **长度约束（两处，容易混淆）**：
  - **目标段**（要转换的音频）走 `whisper_encoder.encode()`，不重采样分块，所以仍受 30s 硬顶；
    `--max-seg-sec 28`、`--num-overlaps 1` 就是为把"段 + 上下文"压进这个上限并控制显存峰值。
  - **prompt 侧**：>30s 时内容特征走 `encode_long()` 按 28s 分块拼接，音色通道 `pt_mel` 直接从波形算，
    真正的上限是 RoPE 4096（约 50s），所以 `--max-prompt 45` 才敢设 45s。

### 9.7 `eval` — 把"像不像 / 稳不稳 / 清不清"量化

- **职责**：对 `vocal.wav` 打分并写 JSON；默认包含 SIM、稳定性与 SingMOS（漏音由下一节的双模型扫描负责）。
- **模型/算法**：
  - **SIM**：ERes2NetV2（`pretrained_eres2netv2w24s4ep4`）说话人嵌入，3s 窗逐窗余弦，
    按"离 prompt 的半音距离"分桶；±0.004 是 seed 噪声底。
  - **稳定性**：1.5s 窗的相邻 drift / 掉音色窗 / 最差窗。
  - **吐字**：FunASR `paraformer-large` + `fsmn-vad`，以原唱 ASR 为参考算 CER（必须固定 VAD 种子）。
  - **自然度**：SingMOS（`tools/singmos` 独立 venv）；NISQA 可选（语音域，仅诊断）。
  - **三角**：`eval_triad` 用 ERes2NetV2 + CAMPPlus 双模型 + impostor 归一化，给"获得/难度/残留"。
  - **天花板**：`eval_sim_ceiling` 先标定"同一个人同一段录音"能拿多少分，否则 SIM 下降无法解读。

### 9.8 `leak-detect` / `leak-repair` — 检测并定点修复"像原唱"

- **职责**：扫全曲 3s 窗，找"输出比参考更接近原唱"的区间（漏音），写 `leak_report.json`；
  `leak-repair` 对命中的跨度重新合成，只在增益门通过时采纳（默认关）。
- **算法**：ERes2NetV2 与 CAMPPlus 双模型各自算 `excess = C − A`（原唱相似度 − 参考相似度），
  用 impostor 池归一化后取**共识窗**；低于地板（0.05 / 0.07）不报。
- **坑**：impostor 池为空时 `excess` 会退化成裸 C，产生误报（已修）；相似度锚点必须一致，
  截断参考会换掉锚点使历史数字不可比。

### 9.9 `mix` — 混回伴奏

- **职责**：`vocal.wav` + `acc.wav` → `mix.wav`。纯信号处理，无模型。
- **算法**：`--match-lead`（默认开）用原唱 `lead.wav` 的逐帧 RMS 包络校正人声（200ms 平滑，
  修正 SVC 在乐句内的 3-5dB 下陷）；`--match-acc`（默认开）让人声增益跟随伴奏包络；软限幅防削波；
  伴奏保留立体声。

### 9.10 MV 侧：`mv.py` 的八个阶段

| 阶段 | 职责 | 用的模型/算法 |
|---|---|---|
| `slice` | 切出 16k `align.wav` + 44.1k `audio.wav`，写 `slice_meta.json` | ffmpeg，无模型 |
| `lyrics` | 抓歌词并转成带逐字时间的增强 LRC | 酷狗 KRC / 网易云 yrc（逐字）/ lrclib，多源回退 |
| `cues` | 歌词 → 口型时间轴 `cues.json` | 中文 pypinyin（strict 取真实韵母）；日文 pyopenjtalk + jaconv；映射到 Rhubarb 的 A/B/C/E 口型；能量门限（−40dB）判行尾，长音做"枣核型"两段式 |
| `beats` | 全曲节拍网格，供渲染的 `--sway` 摇摆 | Beat This! 检测 downbeat + 鲁棒最小二乘拟合 `t = t0 + k·barLen`（抗漏检） |

| `subs` | 烧双行滚动 KTV 字幕 | `make_ass.py` 生成 ASS + `ffmpeg -vf ass` |

## 10. 可复用的经验

1. **先把噪声底测出来**，否则所有 A/B 都在读数噪声。
2. **默认可信度 = 实验可信度**：每个默认值都要能指回一个提交和一张表。
3. **指标会漏掉东西**，发现"听得出但测不出"就去造指标，而不是换参数。
4. **否定结果要写下来**，它节省的是未来重复踩坑的时间（本仓库 15 条否定结论）。
5. **文档与代码同提交**，两个月后再补就变成考古。
6. **架构层要可回滚**：SVS 层 24 小时内的上撤，靠的是"默认值切换 + 旧路径保留"。
7. **性能优化要么等价（bit-identical），要么量出收益**。
8. **缓存必须改协议之外**：缓存"同一个向量"，不改锚点、不改评测口径。
